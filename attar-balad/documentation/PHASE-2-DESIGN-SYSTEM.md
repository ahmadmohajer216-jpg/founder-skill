# فاز ۲ – تحویل دیزاین سیستم

**تاریخ:** ۲۰۲۶/۱۱/۲۱ · **وضعیت:** آمادهٔ بازبینی
**مرجع:** `documentation/PHASE-1-ARCHITECTURE.md` (بخش ۴ – دیزاین سیستم)

---

## ۱. هدف مرحله

تبدیل دیزاین سیستم سند فاز ۱ به کد واقعی: یک منبع یکتای توکن، فونت‌های self-host،
و کتابخانهٔ اجزای پایه با همهٔ حالت‌ها – به‌گونه‌ای که هر صفحهٔ فاز ۳ فقط با ترکیب
همین اجزا ساخته شود و هیچ رنگ یا اندازهٔ خامی دوباره نوشته نشود.

## ۲. خروجی مورد انتظار

- توکن‌های رنگ/تایپ/فاصله/شکل/سایه/حرکت به‌صورت متغیر CSS
- فونت Vazirmatn و Estedad به‌صورت woff2 و self-host (بدون CDN)
- اجزای پایه: دکمه (۴ گونه، ۳ اندازه، ۴ حالت)، فرم (۸ کنترل + خطا/راهنما)،
  نشان، چیپ فیلتر، کارت محصول (۳ حالت)، هدر دسکتاپ، هدر موبایل، نوار ناوبری پایین،
  سبد کشویی، کارت باشگاه، مراحل خرید، پیام/توست، حالت خالی
- صفحهٔ مرجع `design-system.html` که همهٔ موارد بالا را زنده نشان می‌دهد

## ۳. طراحی و کد

| تصمیم | مقدار |
|---|---|
| رنگ اصلی | `#14532D` – دکمه، هدر، لینک فعال |
| مکمل | `#A3CFA5` – نشان و سطح ملایم |
| پس‌زمینه | `#F7F3E8` |
| تأکید | `#C5A45B` – فقط سطح/نشان/خط، نه متن ریز |
| متن | `#292D27`؛ ثانویه `#5B6156` (۵٫۵:۱) |
| تیتر | Estedad 600/700 |
| متن | Vazirmatn 400/500/600/700 |
| مقیاس فاصله | ۴ → ۹۶ (پله‌های ۴/۸/۱۲/۱۶/۲۴/۳۲/۴۸/۶۴/۹۶) |
| شعاع | ۸ / ۱۲ / ۱۶ / ۲۴ / pill |
| حرکت | ۱۶۰–۳۲۰ms، `cubic-bezier(.22,.61,.36,1)`، خاموش با `prefers-reduced-motion` |

پیشوند کلاس‌ها `ab-` است تا با کلاس‌های ووکامرس و قالب پایه تداخل نکند؛ همان کلاس‌ها
در فاز ۴ مستقیماً به Child Theme منتقل می‌شوند.

## ۴. فایل‌های این مرحله

```
attar-balad/
├── design-system.html                    ← صفحهٔ مرجع اجزا (جدید)
├── assets/
│   ├── css/
│   │   ├── tokens.css                    ← رنگ، تایپ، فاصله، شکل، حرکت (جدید)
│   │   └── components.css                ← اجزای پایه (جدید)
│   └── fonts/
│       ├── Vazirmatn-{Regular,Medium,SemiBold,Bold}.woff2   (جدید)
│       ├── Estedad-{SemiBold,Bold}.woff2                    (جدید)
│       └── FONT-LICENSES.md              ← مجوز OFL هر دو فونت (جدید)
└── documentation/
    └── PHASE-2-DESIGN-SYSTEM.md          ← همین سند
```

`index.html` و `styles.css` نسخهٔ نمونهٔ قبلی در این فاز **تغییر نکرده‌اند**؛
پوستهٔ آن‌ها در فاز ۳ روی همین توکن‌ها بازنویسی می‌شود (پالت قبلی `#004d2e` / `#e0b071`
با پالت تأییدشدهٔ برند یکسان نیست).

## ۵. روش اجرا

بدون build و بدون نصب:

1. ریشهٔ وب روی پوشهٔ `attar-balad/` باشد (همان سرویس پیش‌نمایش).
2. `design-system.html` را باز کنید: `/design-system.html`
3. در وردپرس (فاز ۴) همین دو فایل با `wp_enqueue_style` بارگذاری می‌شوند.

## ۶. روش تست

| تست | روش |
|---|---|
| فونت‌ها | در کنسول: `document.fonts.check('16px Vazirmatn')` و `document.fonts.check('700 32px Estedad')` باید `true` بدهند |
| توکن‌ها | `getComputedStyle(document.documentElement).getPropertyValue('--ab-green')` = `#14532d` |
| RTL | همهٔ فاصله‌ها منطقی؛ بدون اسکرول افقی در ۳۶۰px |
| دکمه‌ها | هاور، فوکوس با Tab، غیرفعال، حالت بارگذاری |
| فرم | خطای کد تخفیف زیر همان فیلد؛ فیلد غیرفعال قابل ویرایش نیست |
| کنتراست | متن روی کرم، سبز و طلایی با نسبت‌های ثبت‌شده در صفحه |
| حرکت | با «کاهش حرکت» سیستم، انیمیشن‌ها متوقف می‌شوند |

## ۷. مشکلات احتمالی

- **کش فونت:** فایل woff2 با نام ثابت جایگزین شود، مرورگر ممکن است نسخهٔ قدیمی را نگه دارد؛
  در محیط توسعه کش خاموش است، در محیط واقعی یک نسخه به نام فایل اضافه کنید.
- **`color-mix()`:** فقط در حالت هاور دکمهٔ طلایی استفاده شده؛ در مرورگرهای قدیمی رنگ ثابت
  می‌ماند و چیزی نمی‌شکند.
- **Estedad در دسترس نبود:** متن‌ها به Vazirmatn برمی‌گردند (fallback در `--ab-font-head`).
- **تصاویر سنگین:** تصاویر کتابخانه هنوز به WebP تبدیل نشده‌اند؛ در فاز ۷ انجام می‌شود.

## ۸. معیار تأیید نهایی

1. صفحهٔ مرجع بدون خطای کنسول باز شود.
2. هر دو فونت واقعاً از `assets/fonts` بارگذاری شوند (نه شبکهٔ بیرونی).
3. هیچ رنگ خامی خارج از `tokens.css` در `components.css` نباشد.
4. همهٔ اجزا در ۳۶۰px، ۹۲۰px و ۱۴۴۰px بدون شکست چیدمان دیده شوند.
5. تأیید بصری شما روی صفحهٔ مرجع.
