**نسخه:** ۱٫۰ – ۲۰۲۶/۱۱/۲۰
**وضعیت:** پیش از کدنویسی؛ منتظر تأیید شما
**خروجی این فاز:** معماری نهایی، نقشه صفحات، دیزاین سیستم، اولویت اجرا، وابستگی‌های فنی و برنامه تحویل مرحله‌ای

## ۰. وضعیت فعلی پروژه (نقطه شروع واقعی)

| دارایی | وضعیت | نقش در پروژه |
|---|---|---|
| نمونهٔ استاتیک صفحه اصلی (`index.html` / `styles.css` / `main.js`) | آماده | مرجع بصری و تعیین سطح کیفیت طراحی |
| کتابخانه تصاویر `image-library/` + `IMAGE-STANDARD.md` | آماده | قاعده ثابت تولید و تأیید تصویر |

**نتیجه:** طراحی بصری «جهت» را تعیین کرده است؛ آنچه ساخته می‌شود یک فروشگاه واقعی روی WordPress/WooCommerce است و نمونهٔ استاتیک فقط مرجع است، نه محصول نهایی.

## ۱. تحلیل نیازمندی‌ها

### ۱٫۱ کاربران و نقش‌ها

| نقش | هدف اصلی | نکته کلیدی تجربه |
|---|---|---|
| خریدار مهمان | رسیدن سریع به محصول و خرید بدون ثبت‌نام اجباری | خرید مهمان مجاز، ثبت‌نام پیشنهادی پس از خرید |
| مشتری عضو | پیگیری سفارش، آدرس‌ها، علاقه‌مندی‌ها | یک‌بار ورود، همه‌چیز در «حساب من» |
| عضو باشگاه | دیدن امتیاز، سطح و جوایز | نمایش امتیاز در هدر و داشبورد |
| مدیر فروشگاه | محصول، موجودی، سفارش، تخفیف | مدیریت کامل بدون نیاز به کدنویسی |
| نویسنده/سردبیر مجله | انتشار مقاله با منابع معتبر | نقش جدا با دسترسی محدود |

### ۱٫۲ نیازمندی‌های کارکردی (با معیار پذیرش)

**الف) کشف محصول**
- جست‌وجوی فوری (نام فارسی، نام علمی، مترادف‌ها) با پیشنهاد زنده
- فیلتر: دسته، قیمت، وزن/بسته‌بندی، موجودی، برچسب (ارگانیک/ویژه)
- مرتب‌سازی: پرفروش، جدید، ارزان، گران
- **معیار پذیرش:** هر فیلتر بدون رفرش کامل صفحه اعمال شود و آدرس قابل اشتراک باشد.

**ب) صفحه محصول**
- گالری، قیمت و قیمت تخفیفی، وزن و بسته‌بندی، موجودی، تعداد
- افزودن به سبد (AJAX) و به علاقه‌مندی‌ها
- توضیحات، ترکیبات، مشخصات، روش مصرف، شرایط نگهداری، هشدارها
- دیدگاه مشتریان (فقط خریدار تأییدشده)، پرسش‌های متداول، محصولات مرتبط
- **معیار پذیرش:** افزودن به سبد بدون بارگذاری مجدد و با به‌روزرسانی فوری شمارنده؛ محصول ناموجود دکمهٔ غیرفعال با پیام روشن داشته باشد.

**ج) خرید**
- سبد کشویی + صفحه سبد، کد تخفیف، محاسبهٔ ارسال
- تسویه: آدرس، روش ارسال، درگاه پرداخت
- تأیید سفارش، ایمیل/پیامک وضعیت، پیگیری با کد سفارش
- **معیار پذیرش:** یک خرید تست کامل (محصول → پرداخت → تأیید → پیگیری) بدون خطا و بدون کالای باقی‌مانده در سبد.

**د) حساب کاربری**
- ورود/ثبت‌نام با موبایل (کد یک‌بارمصرف) و ایمیل
- داشبورد، سفارش‌ها، آدرس‌ها، جزئیات حساب، علاقه‌مندی‌ها، پیگیری مرسوله، تغییر رمز
- **معیار پذیرش:** هر صفحه فقط با نشست معتبر همان کاربر باز شود (بدون دسترسی به داده دیگری).

**هـ) باشگاه مشتریان**
- کارت عضویت با شمارهٔ عضویت، امتیاز جاری، سطح (Bronze/Silver/Gold/VIP)، تاریخچهٔ امتیاز
- قواعد امتیاز، کدهای تخفیف اختصاصی، پاداش معرفی دوستان
- **معیار پذیرش:** امتیاز پس از تکمیل سفارش به‌صورت خودکار و یک‌بار ثبت شود؛ تاریخچه قابل رهگیری باشد؛ امتیاز دستی قابل تنظیم توسط مدیر.

**و) محتوا (مجله)**
- صفحه اصلی مجله، دسته‌بندی، مقالهٔ ویژه، نویسنده، زمان مطالعه، مقالات مرتبط، اشتراک‌گذاری
- **قاعده:** هر ادعای سلامتی باید به منبع معتبر ارجاع دهد؛ در نبود منبع، متن بازنویسی می‌شود.

**ز) اطلاع‌رسانی و پشتیبانی**
- پیامک/ایمیل: ثبت سفارش، پرداخت، ارسال، تحویل، بازنشانی رمز
- چت/واتس‌اپ/دایرکت به‌عنوان کانال پشتیبانی (لینک، نه ربات ساختگی)

**ح) مدیریت**
- ورود محصول از CSV/JSON، مدیریت موجودی، کوپن، سفارش، اعضای باشگاه، گزارش فروش، نقش نویسنده

### ۱٫۳ نیازمندی‌های غیرکارکردی

| حوزه | هدف قابل سنجش |
|---|---|
| سرعت | LCP < ۲٫۵ ثانیه روی ۴G موبایل؛ JS اولیه < ۲۰۰KB؛ تصاویر WebP/AVIF |
| امنیت | HTTPS اجباری، nonce روی همه فرم‌ها، sanitize/escape، prepared statements، محدودسازی ورود، ۲FA مدیر |
| سئو | Schema محصول/مقاله/FAQ، sitemap، متای یکتا، Alt تصویر، ساختار Heading |
| دسترس‌پذیری | WCAG 2.1 AA: کنتراست، فوکوس مرئی، aria-label، ناوبری با کیبورد |
| RTL | چیدمان واقعی راست‌به‌چپ، اعداد فارسی در رابط |
| پشتیبان‌گیری | روزانه، نگهداری ۳۰ روز، بازیابی آزمایش‌شده (RPO ۲۴ ساعت) |
| مقیاس | ۵۰۰ محصول و ۵۰۰۰ سفارش در سال بدون افت محسوس |

### ۱٫۴ فرض‌ها و محدودیت‌ها

1. پشتهٔ الزامی: WordPress + WooCommerce؛ بنابراین «فروشگاه واقعی» = WooCommerce، نه فروشگاه سفارشی از صفر.
2. پرداخت با درگاه ایرانی (زرین‌پال) – نیازمند مرچنت و تأیید شما.
3. پیامک نیازمند پنل پیامکی (پیشنهاد: کاوه‌نگار) – نیازمند کلید.
4. تصاویر تابع `IMAGE-STANDARD.md` هستند؛ تصویر بدون تأیید وارد سایت نمی‌شود.
5. اطلاعات محصول و مشتری ساختگی وارد محیط واقعی نمی‌شود؛ دادهٔ نمایشی فقط در محیط توسعه.
6. محتوای درمانی بدون منبع منتشر نمی‌شود.

### ۱٫۵ ریسک‌ها و پاسخ

| ریسک | اثر | پاسخ |
|---|---|---|
| تصاویر آماده نبودن برای ۴۹ محصول | تأخیر راه‌اندازی کاتالوگ | راه‌اندازی با محصولات تصویردار؛ بقیه با وضعیت «به‌زودی» |
| کندی ووکامرس با افزونه‌های زیاد | افت نرخ تبدیل | حداقل افزونه، کش شیء، Gutenberg به‌جای Elementor |
| نبود منبع برای ادعاهای درمانی | ریسک حقوقی | فیلد «منبع» اجباری پیش از انتشار مقاله/محصول |
| وابستگی به یک درگاه | توقف فروش | معماری پرداخت مستقل از درگاه (adapter) |
| نبود محتوای فارسی اصیل | سئوی ضعیف | تقویم محتوایی ۱۲ مقاله در فاز ۵ |

## ۲. معماری نهایی

### ۲٫۱ پشتهٔ فنی

| لایه | انتخاب | دلیل |
|---|---|---|
| CMS | WordPress 6.x | الزام پروژه، بلوغ و اکوسیستم |
| فروشگاه | WooCommerce 9.x | سبد، سفارش، مالیات، کوپن آماده |
| PHP | 8.2+ (FPM) | سرعت و پشتیبانی فعال |
| دیتابیس | MySQL 8 / MariaDB 10.6، `utf8mb4` | الزام ووکامرس |
| وب‌سرور | Nginx + PHP-FPM | سرعت و کش |
| کش | Redis (object cache) + کش صفحه | کاهش کوئری |
| قالب | Child Theme اختصاصی روی قالب سبک پایه | کنترل کامل، بدون قفل شدن |
| ساخت صفحات | **Gutenberg + بلاک‌های اختصاصی** (نه Elementor) | سبک‌تر، کد تمیزتر، سرعت بهتر |
| افزونهٔ اختصاصی | `attar-balad-core` | منطق کسب‌وکار جدا از قالب |

> **توصیهٔ صریح:** Elementor حذف شود. همان طراحی با بلاک‌های اختصاصی + CSS انجام می‌شود؛ نتیجه سبک‌تر و قابل نگهداری‌تر است. اگر تیم محتوا به صفحه‌ساز بصری نیاز دارد، Elementor فقط برای صفحات بازاریابی و به‌صورت محدود.

### ۲٫۳ مدل داده

**استاندارد ووکامرس (بدون تغییر ساختار):** محصول، متغیر، سفارش، مشتری، کوپن، مالیات.

**جدول اختصاصی گیاهان (فقط دادهٔ تخصصی، نه جایگزین محصول):**

```sql
CREATE TABLE wp_ab_plants (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  product_id BIGINT UNSIGNED NOT NULL,
  botanical_name VARCHAR(150) NOT NULL,
  description TEXT NULL,
  origin VARCHAR(150) NULL,
  plant_part VARCHAR(100) NULL,
  usage_instructions TEXT NULL,
  storage_instructions TEXT NULL,
  warnings TEXT NULL,
  source_ref VARCHAR(255) NULL,          -- منبع ادعاهای سلامتی
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  UNIQUE KEY uniq_product (product_id),
  KEY idx_botanical (botanical_name),
  CONSTRAINT fk_plant_product FOREIGN KEY (product_id) REFERENCES wp_posts(ID) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

**باشگاه مشتریان (دفتر کل، برای حسابرسی):**

```sql
CREATE TABLE wp_ab_club_ledger (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
  user_id BIGINT UNSIGNED NOT NULL,
  order_id BIGINT UNSIGNED NULL,
  points INT NOT NULL,                    -- مثبت: کسب، منفی: مصرف
  reason VARCHAR(60) NOT NULL,            -- order, redeem, referral, manual
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  KEY idx_user (user_id, created_at)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

امتیاز جاری = مجموع دفتر کل (کش‌شده در user meta). سطح از امتیاز/خرید سالانه محاسبه می‌شود.

**علاقه‌مندی‌ها:** جدول سبک `wp_ab_wishlist (user_id, product_id, created_at)` با کلید یگانه.

**مهاجرت:** هر تغییر ساختار در `database/migrations/` با شمارهٔ نسخه؛ اجرای idempotent؛ پشتیبان پیش از اجرا.

### ۲٫۴ ماژول‌های افزونهٔ اختصاصی

1. `plants` – فیلدهای تخصصی گیاه + نمایش در تب محصول + اعتبارسنجی منبع
2. `import` – CSV/JSON، dry-run، گزارش خطا، کلید یکتای SKU/slug (اجرای دوباره بدون تکرار)
3. `club` – امتیاز، سطح، جوایز، کد تخفیف اختصاصی، معرفی دوستان
4. `wishlist` – افزودن/حذف، صفحه حساب، شمارنده
5. `notify` – پیامک/ایمیل رخدادهای سفارش (صف + تلاش مجدد)
6. `tracking` – کد رهگیری و صفحهٔ پیگیری سفارش مهمان
7. `search` – جست‌وجوی وزن‌دار فارسی (نام، نام علمی، مترادف) + پیشنهاد زنده
8. `filters` – فیلترهای Ajax بدون بارگذاری صفحه

### ۲٫۵ یکپارچه‌سازی‌ها

| سرویس | کاربرد | نوع |
|---|---|---|
| زرین‌پال | پرداخت آنلاین | کلید مرچنت (سکرت) |
| کاوه‌نگار (پیشنهادی) | پیامک وضعیت | کلید API (سکرت) |
| SMTP تراکنشی | ایمیل سفارش | اعتبارنامه (سکرت) |
| Google Analytics 4 / Matomo | تحلیل رفتار | شناسه |
| اینماد | نماد اعتماد | کد |

هیچ کلیدی در کد یا مخزن قرار نمی‌گیرد؛ همه از متغیر محیطی/سکرت خوانده می‌شوند.

### ۲٫۶ امنیت

- HTTPS اجباری + HSTS؛ کوکی‌های نشست `Secure`/`HttpOnly`
- nonce برای هر فرم و درخواست AJAX؛ CSRF روی سبد و پرداخت
- `sanitize_*` روی ورودی، `esc_*` روی خروجی؛ کوئری‌ها فقط با `$wpdb->prepare`
- کنترل دسترسی با capability؛ نقش نویسنده محدود
- محدودسازی تلاش ورود، ۲FA برای مدیر، مسدودسازی XML-RPC
- لاگ رخدادهای حساس (تغییر قیمت، حذف سفارش، تنظیم امتیاز)
- پشتیبان روزانه خارج از سرور + بازیابی آزمایشی ماهانه

### ۲٫۷ محیط‌ها و استقرار

| محیط | کاربرد | پیکربندی |
|---|---|---|
| Local (همین سندباکس) | توسعه و تست | Docker: php-fpm، nginx، mysql، redis، wp-cli |
| Staging | بازبینی مشتری و تست پرداخت | کپی دادهٔ بی‌نام‌شده، `noindex` |
| Production | فروش واقعی | SSL، کش، پشتیبان، مانیتورینگ |

استقرار: تغییرات از طریق Git → اجرای migration → پاک‌سازی کش. هیچ فایلی مستقیم روی سرور ویرایش نمی‌شود.
