# عطار بلد — فروشگاه اینترنتی گیاهان دارویی

نسخه‌ی اجرایی وب‌سایت «عطار بلد» با طراحی سلطنتی ایرانی، دوزبانه (فارسی RTL / انگلیسی LTR)
و صفحات کامل فروشگاه، حساب کاربری و پنل مدیریت.

> **این نسخه، نمایشی است.** محصولات، قیمت‌ها، موجودی و نظرات نمونه‌اند و با برچسب «نمونه»
> مشخص شده‌اند. درگاه پرداخت واقعی، ایمیل واقعی و پایگاه داده‌ی سروری متصل نیست.
> همه‌ی داده‌های کاربر (سبد، سفارش، حساب) در `localStorage` همین مرورگر ذخیره می‌شوند.

---

## ۱. اجرا

سایت یک اپلیکیشن استاتیک است و هیچ مرحله‌ی build ندارد:

```
attar-balad/index.html
```

در محیط Base44، سرویس `preview` در `docker-compose.base44.yml` این پوشه را روی پورت ۳۰۰۰
سرو می‌کند (`static_server.py`). برای اجرای محلی کافی است یک وب‌سرور ساده روی همین پوشه اجرا شود:

```bash
cd attar-balad && python3 -m http.server 3000
```

سپس `http://localhost:3000/` را باز کنید. مسیرها هش‌محور هستند (`#/shop`, `#/product/...`)
تا روی هر میزبان استاتیکی بدون تنظیم rewrite کار کنند.

## ۲. حساب‌های نمایشی

| نقش | ایمیل | گذرواژه |
| --- | --- | --- |
| مدیر | `admin@attar-balad.example` | `admin1234` |
| مشتری | `sara@example.com` | `sara1234` |

گذرواژه‌ها فقط با یک هش ساده‌ی محلی ذخیره می‌شوند و **احراز هویت واقعی نیستند**. برای تولید،
باید احراز هویت به سرویس سروری با نشست امن و هش استاندارد (مثلاً Argon2/bcrypt) منتقل شود.

## ۵. مدل داده و نگاشت به WooCommerce

داده‌ها در `data/catalog.js` و `data/content.js` با ساختار زیر نگهداری می‌شوند. همین شکل
برای انتقال به WooCommerce طراحی شده است:

| موجودیت این پروژه | معادل WooCommerce / WordPress | یادداشت |
| --- | --- | --- |
| `categories[]` | `product_cat` | `id`/`slug` قابل نگاشت به ترم |
| `products[]` | `product` (نوع simple/variable) | `slug`, `name`, `desc` |
| `products[].variants[]` | variation | وزن/بسته‌بندی با قیمت و موجودی مستقل |
| `products[].specs[]` | attributes | جفت برچسب/مقدار |
| `products[].art` | featured image | تصویرسازی SVG جایگزین رسانه واقعی |
| `state.cart[]` | cart item (session) | `pid` + `vid` + `qty` |
| `state.orders[]` | `shop_order` | کد سفارش، وضعیت، اقلام، جمع |
| `state.users[]` | `customer` / `user` | نقش `admin` / `customer` |
| `state.reviews[]` | `comment` (product review) | وضعیت `approved` / `pending` |
| `state.wishlist[]` | YITH Wishlist یا مشابه | فهرست شناسه محصول |
| `state.newsletter[]` | Mailchimp/Newsletter | ایمیل و زمان عضویت |
| `state.addresses[]` | customer billing/shipping | نشانی‌های ذخیره‌شده |
| `articles[]` | `post` | دسته، تاریخ، متن HTML |
| `plants[]` | custom post type | دانشنامه گیاه |
| `state.overrides{}` | product meta | تغییر قیمت/موجودی از پنل مدیریت |

**چه چیزی پیاده‌سازی شده است؟** صفحه اصلی، فروشگاه با جست‌وجوی واقعی روی کاتالوگ، فیلتر دسته/قیمت/موجودی/تخفیف/جدید، مرتب‌سازی و صفحه‌بندی؛ صفحه محصول با تنوع وزن، گالری، تب‌ها و نظرات؛ سبد خرید پایدار؛ تسویه‌حساب با اعتبارسنجی و ثبت سفارش آزمایشی؛ حساب مشتری؛ پنل مدیریت با ویرایش محصول، تغییر وضعیت سفارش و تأیید نظر؛ دوزبانگی کامل؛ مجله، دانشنامه، تاریخ و تور باغ.

**چه چیزی نیازمند سرویس بیرونی است؟** پرداخت واقعی (درگاه بانکی/استرایپ/پی‌پال)، ارسال ایمیل خبرنامه و بازیابی رمز، ذخیره‌سازی سروری سفارش‌ها، و هوش مصنوعی.

**آیا اتصال واقعی WooCommerce وجود دارد؟** نه. هیچ API یا افزونه‌ای متصل نشده و هیچ داده‌ای به ووکامرس منتقل نشده است. ساختار داده فقط برای نگاشت آینده آماده است.

**آیا داده‌ها قابل انتقال هستند؟** بله؛ کاتالوگ JSON است و می‌توان آن را با یک اسکریپت به محصولات ووکامرس تبدیل کرد، اما این اسکریپت نوشته و آزمایش نشده است.

## ۶. هوش مصنوعی

دستیار پایین صفحه یک **جست‌وجوی محلی قاعده‌محور** است: پرسش را با نام محصول، گیاه، دسته و
صفحات سایت تطبیق می‌دهد و پاسخ را از همان کاتالوگ می‌سازد. هیچ سرویس هوش مصنوعی، کلید API
یا درخواست شبکه‌ای وجود ندارد و در رابط کاربری هم صریحاً «نسخه نمایشی، بدون هوش مصنوعی»
اعلام می‌شود. دستیار هرگز تشخیص یا تجویز درمانی ارائه نمی‌کند.

برای اتصال واقعی، پاسخ‌ها باید از یک سرویس سروری با کلید محافظت‌شده بیایند، به داده‌ی
تأییدشده محدود شوند و پیش‌نویس محتوای تولیدشده پیش از انتشار تأیید مدیر بگیرد.

## ۷. امنیت و آنچه باید در تولید تغییر کند

- **احراز هویت:** محلی و نمایشی است؛ در تولید باید به نشست سروری و هش استاندارد منتقل شود.
- **قیمت و موجودی:** در مرورگر محاسبه می‌شود؛ در تولید باید سبد و مبلغ نهایی در سرور
  بازمحاسبه و اعتبارسنجی شود.
- **کنترل دسترسی:** نقش مدیر فقط در همان مرورگر بررسی می‌شود؛ در تولید باید در سرور و
  با کنترل دسترسی پایگاه داده اعمال شود.
- **اطلاعات پرداخت:** هیچ داده‌ی بانکی دریافت یا ذخیره نمی‌شود؛ پرداخت «آزمایشی» است.
- **اعتبارسنجی ورودی:** فرم‌های تسویه، نظر، تماس و خبرنامه در سمت مرورگر اعتبارسنجی می‌شوند؛
  اعتبارسنجی سروری لازم است.
- **XSS:** متن‌های کاربر (نام، نظر، پیام) با `esc()` پیش از درج در HTML پاک‌سازی می‌شوند.

## ۸. سئو و دسترس‌پذیری

- عنوان و توضیحات متا برای هر مسیر به‌روزرسانی می‌شود.
- داده ساختاریافته `Product` و `Article` (JSON-LD) در صفحه محصول و مقاله درج می‌شود.
- هر تصویر متن جایگزین توصیفی دارد؛ ساختار هدینگ صفحه‌ها یکتا و مرتب است.
- `lang` و `dir` سند با تغییر زبان عوض می‌شوند؛ پیوند پرش به محتوا، `aria-live` برای
  پیام‌ها، `aria-pressed`/`aria-selected` برای کنترل‌ها و فوکوس مرئی برای صفحه‌کلید.
- تصویرسازی‌ها SVG هستند و در هر اندازه شارپ می‌مانند؛ تصویر واقعی محصول باید در تولید
  با فرمت بهینه (WebP/AVIF) و ابعاد مشخص جایگزین شود.

## ۹. آنچه آزمایش نشده یا باقی مانده است

- پرداخت واقعی، ایمیل واقعی، پیامک و حساب کاربری سروری.
- قابلیت سه‌بعدی/VR تور باغ (فقط گالری تعاملی پیاده‌سازی شده است).
- نمادهای اعتماد (اینماد و درگاه) — جای‌نگهدار هستند و تأیید نشده‌اند.
- آپلود تصویر محصول از پنل مدیریت (فعلاً تصویرسازی خودکار دسته استفاده می‌شود).
- انتقال واقعی داده به WooCommerce.
- تست خودکار مرورگر (تست‌های این نسخه دستی و در پیش‌نمایش انجام شده است).

## ۱۰. چک‌لیست بررسی دستی

1. صفحه اصلی: هیرو، میان‌برها، نوار خدمات، ۸ دسته، بنر تاریخ، سه کارت محتوایی،
   پرفروش/جدید/تخفیف، معرفی برند، مجله، نظرات، خبرنامه.
2. فروشگاه: جست‌وجوی «زعفران»، فیلتر دسته، محدوده قیمت، فقط موجود، مرتب‌سازی، صفحه ۲.
3. محصول: تغییر وزن، تغییر تعداد، افزودن به سبد، علاقه‌مندی، تب مشخصات، ثبت نظر.
4. سبد و تسویه: تغییر تعداد، حذف، اعتبارسنجی فرم، ثبت سفارش، پرداخت آزمایشی.
5. حساب: ورود مشتری، سفارش‌ها، نشانی جدید، علاقه‌مندی‌ها.
6. مدیریت: ورود مدیر، ویرایش قیمت محصول، تغییر وضعیت سفارش، تأیید نظر.
7. زبان: تغییر به انگلیسی و بازگشت؛ جهت صفحه و ترجمه‌ها.
8. موبایل: منوی کشویی، عدم اسکرول افقی، کارت‌های لمسی، تسویه‌ی یک‌ستونه.
